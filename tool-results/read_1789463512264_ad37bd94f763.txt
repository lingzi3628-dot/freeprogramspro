    73→1. Executive Summary
    74→Free Programs Pro Store is a multi-platform software marketplace and app store where an administrator and authorized developers publish free programs for Windows, Linux/Ubuntu, Android, and Chrome Extensions. The public site is a browse-and-download storefront with a Play Store-style experience. A private admin panel handles app creation, version management, binary uploads, malware scanning, publication, and analytics.
    75→
    76→The product is delivered as:
    77→
    78→A web storefront (public)
    79→
    80→An admin panel (private)
    81→
    82→A Progressive Web App installable on phones, tablets, and desktops
    83→
    84→It is not a general-purpose app store for third-party developers. It is a curated, admin-controlled catalog, with optional future support for external uploader accounts under moderation.
    85→
    86→2. Vision & Goals
    87→Vision
    88→Become the cleanest, most trustworthy place to discover and download free software across desktop, mobile, and browser — with transparent checksums, verified files, and no piracy.
    89→
    90→Primary Goals
    91→Let an admin upload, version, and publish apps across four platforms in under 5 minutes per app.
    92→
    93→Give visitors a Play Store-quality browsing experience on phone and desktop.
    94→
    95→Establish trust through checksums, scan status, licensing, and source URLs.
    96→
    97→Be installable as a PWA on every major platform.
    98→
    99→Achieve Lighthouse ≥ 95 (mobile) on public pages.
   100→
   101→Success Metrics (first 6 months)
   102→Metric  Target
   103→Apps published  100+
   104→Monthly downloads       50K
   105→PWA install rate        ≥ 3% of returning visitors
   106→Bounce on app detail    ≤ 40%
   107→Median LCP (mobile)     < 2.0s
   108→Admin publish time      < 5 min/app
   109→3. Non-Goals
   110→Not a paid app store (v1). Donations/Pro membership are optional add-ons.
   111→
   112→Not a piracy or warez host. Only apps the operator owns or is licensed to distribute.
   113→
   114→Not a developer SDK marketplace in v1.
   115→
   116→Not a code signing service.
   117→
   118→Not a replacement for GitHub Releases for source distribution.
   119→
   120→Not a desktop-native installer framework.

   122→4. Target Users & Personas
   123→Persona A — Sam, casual visitor (mobile)
   124→Wants a free PDF tool for Android. Lands from Google. Wants to find it, trust it, download it, in under 60 seconds. Cares about ratings, size, and "is it safe?"
   125→
   126→Persona B — Priya, power user (desktop)
   127→Needs a specific Linux .deb. Cares about architecture (amd64/arm64), distro, dependency notes, checksum, and version history. Will verify SHA-256 before installing.
   128→
   129→Persona C — Marco, uploader (future role)
   130→Has built a Chrome extension. Wants to submit it for review. Needs a submission portal, status updates, and version management.
   131→
   132→Persona D — The Admin (primary operator)
   133→Owns the site. Uploads everything. Needs a fast, reliable dashboard: create app → upload files → set versions → publish. Wants analytics, moderation queues, and audit logs.
   134→
   135→Persona E — Moderator
   136→Handles user reports, review moderation, takedown requests. Needs a queue-first UI.

   218→7.1 Design Principles
   219→Principle       Description
   220→Content-first   Icon, name, rating, badge do the work. Chrome stays quiet.
   221→One primary action      Every card/detail has one loud button: Download.

   223→Progressive disclosure  Summary first, expandable detail.
   224→Two shapes, one product Phone and desktop are the same product, different shells.
   225→Feels native    Installable PWA, safe-area aware, 60fps scroll.
