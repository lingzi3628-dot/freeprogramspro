1. Executive Summary
Free Programs Pro Store is a multi-platform software marketplace and app store where an administrator and authorized developers publish free programs for Windows, Linux/Ubuntu, Android, and Chrome Extensions. The public site is a browse-and-download storefront with a Play Store-style experience. A private admin panel handles app creation, version management, binary uploads, malware scanning, publication, and analytics.

The product is delivered as:

A web storefront (public)

An admin panel (private)

A Progressive Web App installable on phones, tablets, and desktops

It is not a general-purpose app store for third-party developers. It is a curated, admin-controlled catalog, with optional future support for external uploader accounts under moderation.

2. Vision & Goals
Vision
Become the cleanest, most trustworthy place to discover and download free software across desktop, mobile, and browser — with transparent checksums, verified files, and no piracy.

Primary Goals
Let an admin upload, version, and publish apps across four platforms in under 5 minutes per app.

Give visitors a Play Store-quality browsing experience on phone and desktop.

Establish trust through checksums, scan status, licensing, and source URLs.

Be installable as a PWA on every major platform.

Achieve Lighthouse ≥ 95 (mobile) on public pages.

Success Metrics (first 6 months)
Metric	Target
Apps published	100+
Monthly downloads	50K
PWA install rate	≥ 3% of returning visitors
Bounce on app detail	≤ 40%
Median LCP (mobile)	< 2.0s
Admin publish time	< 5 min/app
3. Non-Goals
Not a paid app store (v1). Donations/Pro membership are optional add-ons.

Not a piracy or warez host. Only apps the operator owns or is licensed to distribute.

Not a developer SDK marketplace in v1.

Not a code signing service.

Not a replacement for GitHub Releases for source distribution.

Not a desktop-native installer framework.

4. Target Users & Personas
Persona A — Sam, casual visitor (mobile)
Wants a free PDF tool for Android. Lands from Google. Wants to find it, trust it, download it, in under 60 seconds. Cares about ratings, size, and "is it safe?"

Persona B — Priya, power user (desktop)
Needs a specific Linux .deb. Cares about architecture (amd64/arm64), distro, dependency notes, checksum, and version history. Will verify SHA-256 before installing.

Persona C — Marco, uploader (future role)
Has built a Chrome extension. Wants to submit it for review. Needs a submission portal, status updates, and version management.

Persona D — The Admin (primary operator)
Owns the site. Uploads everything. Needs a fast, reliable dashboard: create app → upload files → set versions → publish. Wants analytics, moderation queues, and audit logs.

Persona E — Moderator
Handles user reports, review moderation, takedown requests. Needs a queue-first UI.

13. Upload & Publishing Flow
Single-app flow:

Create app → name, slug, tagline, category

Upload media → icon, feature graphic, screenshots

Add platform entry → pick platform

Add version → number, channel, min OS, arch, changelog

Upload binary → progress → SHA-256 computed → optional scan

Set trust metadata → license, source URL, permissions

Preview → open public URL in preview mode

Publish → confirmation lists exactly what goes live

Post-publish → app appears in browse, sitemap updates, search index updated

Bulk upload (v1.1): CSV + ZIP bundle.

Scheduled publish: choose date/time; cron job flips status.
